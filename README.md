# LayerDeck

パーツごとに別キャンバスで描いた**透過PNGを、フォルダに書き出すだけで自動的に重ね合わせて**
プレビューするデスクトップアプリ。

A2 のような大きなキャンバスで、ペイントソフト側のレイヤー数を増やさずに全体像を確認するためのもの。
印刷の規格に合っているか、切り抜き（ダイカット）でどんな形になるかも確かめられる。

**ダウンロード**：[最新版のリリース](https://github.com/ken1208git/layerdeck/releases/latest) から
`LayerDeck_<版>_x64-setup.exe` を落として実行する（Windows 10 / 11）。

## 何ができるか

- 作業フォルダを監視し、PNG が増えた／上書きされたら**自動で反映**
- **原寸まで拡大しても軽い**。何倍に拡大しても、絵が何枚あっても、使うメモリはほぼ一定
- レイヤーの表示切替・不透明度・**合成モード17種**・並べ替え（▲▼ / ドラッグ / 名前順）
- レイヤーごとの位置のずらし・拡大率・左右反転
- 左右反転チェック、**明度チェック**（グレー表示）、背景の切り替え
- **規格チェック**：用紙と解像度を選ぶと、ibis で作るべきピクセル数と、各画像が合っているかを表示
- **解像度（dpi）を画像から自動で読み取り**（PNG の pHYs、JPEG の JFIF）
- **カットライン予想**：切り抜き印刷で「絵の輪郭から N mm 外側」で切ったときの形を表示
- **透明チェック**：半透明のにじみや、ほとんど見えない薄い部分を色分け
- ガイド：仕上がり線（塗り足しの内側）・中心線・三分割線
- 確認用の合成PNGを書き出し（倍率を選べる。解像度とカラープロファイルを埋め込み）
- 設定は作業フォルダの `layerdeck.project.json` に自動保存され、次回そのまま復元
- 前回のフォルダ、ウィンドウの大きさと位置を覚えている（画面からはみ出す分だけ直す）

## 使い方

1. `LayerDeck.exe` を起動（インストール版ならスタートメニューから）
2. 「フォルダを選ぶ」でパーツPNGを置くフォルダを指定（次回からは自動で開く）
3. ペイントソフトの各キャンバスから、そのフォルダに透過PNGを書き出す
4. 描き直したら**同じ名前で上書き**すると、表示が差し替わる

### 運用のコツ

- ファイル名を `01_背景.png` `02_キャラ.png` … のように**番号から始める**と、
  番号の小さいものが下に積まれる（後から足したファイルも名前順の位置に入る）。
- **名前を途中で変えない**。変えると別のレイヤー扱いになり、順番や合成モードの設定が引き継がれない。
- 全パーツを**同じキャンバスサイズ**で書き出す。「用紙・解像度」で用紙を選ぶと、合っているか一覧に出る。
- 古い版は作業フォルダの中に別フォルダを作ってそこへ移す（直下しか見ないので無視される）。
- PNG を消したり移したりすると、一覧からも外れる。そのレイヤーの設定（順番・不透明度・合成モードなど）は
  覚えているので、同じ名前のファイルを戻せば元どおりに出る。
- 右上の表示が「✓ 最新の状態」なら、フォルダの中の PNG がすべて反映されている。
  保存した直後は「読み込み中」になる。
- 60枚を超えるフォルダは読み込みを止める（うっかり別のフォルダを選んだとき用）。

### ショートカット

| キー | 動作 |
|---|---|
| ホイール ／ ドラッグ | ズーム ／ 移動 |
| `F` | 全体表示 |
| `1` | 実寸（100% ＝ 画面の1ピクセルに画像の1ピクセル） |
| `H` ／ `G` ／ `T` | 左右反転 ／ 明度チェック ／ 透明チェック |
| `B` | 背景の切り替え（市松／白／灰／黒） |
| 目のアイコンを Alt+クリック | そのレイヤーだけ表示 |

## 規格チェックとカットライン予想

「用紙・解像度」で用紙（A0〜A6、B0〜B6、自由入力）を選ぶと、次を表示する。

- **ibis で作る大きさ**（例：A2 横・250dpi → 5846 × 4134 px）。ibis はキャンバスをピクセル数で指定するため
- 全レイヤーが規格どおりか（「✓ 8枚すべて規格どおり」）。合っていないレイヤーだけ、一覧の行に
  「塗り足しが無い」「縦横比が違う」「A2だと約○dpi」などと理由を出す
- 画像に記録された dpi が画像ごとに違う場合の警告

解像度は、手入力しない限り画像に記録された値を使う。塗り足しは四角く刷る場合の値で、
切り抜き（ダイカット）なら 0 にする。

**カットライン予想**（ガイド → カットライン予想）は、表示中のレイヤーを重ねた結果のうち
不透明度 10% 以上を「絵」とみなし、その輪郭から指定 mm 外側の線を引く。あわせて

- 形がいくつに分かれているか（離れた光の粒などは別の塊になる）
- キャンバスからはみ出すか、端まで何mmあるか

を表示する。プリオの「カットライン作成オプション」は絵の約10mm外側に線を作るので、初期値は 10mm。
あくまで目安で、実際の線は印刷所が作る。

**透明チェック**は、不透明＝灰、半透明＝橙、ほぼ透明＝赤で色分けする。ぼかしやグローのにじみ、
見えにくい薄い部分が切り抜きの形に含まれてしまわないかを確かめるためのもの。
線のふちが細く橙になるのは、ふちのなめらかさ（アンチエイリアス）なので正常。

## 書き出しについて

> **書き出しは確認用です。そのまま納品しないでください。**
> 最終的な統合と納品は、描いたソフト側（ibisPaint など）で行ってください。

「書き出し…」でダイアログが開き、倍率（原寸 / 1/2 / 1/4 / 1/8）を選べる。用紙の物理サイズは変わらず、
解像度だけが下がる。保存先は作業フォルダの `_export`、ファイル名は現地時刻入り
（`check_20260927_143012_1447x2046.png`）。

書き出したPNGには解像度（pHYs）と sRGB を埋め込む。無いと Photoshop 等で 72dpi 扱いになり、
A2 のつもりのファイルが巨大な絵として開かれてしまう。

ブラウザのキャンバスには約2億7千万画素という上限があり、超えると例外を出さずに真っ白な画像になる。
実際に描けるか確かめてから処理し、超える場合は「倍率を下げてください」と止める。

## 動作環境

Windows 10 / 11。WebView2 は Windows に標準で入っているため、通常は追加のインストール不要
（インストーラ版は、入っていなければ自動で取得する）。

## 困ったとき

- **ログ**：「LayerDeck について」→「ログを表示」。
  `%LOCALAPPDATA%\com.layerdeck.desktop\logs\layerdeck.log` に、エラーや起動・書き出しの記録が残る。
- **設定を保存できない**と表示される：作業フォルダに書き込めない（読み取り専用の共有など）。
- **最初からやり直したい**：作業フォルダの `layerdeck.project.json` を消すと初期状態で開く。

## 仕組み

PNG は途中の行だけを取り出せない形式なので、「見えている部分だけ読む」ことが原理的にできない。
そこで**読み込み時に一度だけフル展開し、1024px のマス目（タイル）に切り分けて持つ**。

```
PNGが更新される
  ↓ ① Web Worker がフル展開（worker の中だけに存在し、終わったら即解放）。dpi もここで読む
  ↓ ② 1024px のマス目に切り分け、粗い段から順に返す
  ↓ ③ 以降は画面に映っているマス目だけを展開して描く
```

使用メモリは **画像サイズ × 枚数 ではなく、表示領域の広さ**で決まる。展開量の上限は
**空き物理メモリの 25%**（96MB〜1.5GB）に自動で追従し、ペイントソフトが重くなれば LayerDeck が身を引く。
**ディスクにキャッシュは作らない。**

カットライン予想は、粗い段のマス目から約0.4mm単位の格子に不透明度を集め、
距離変換（Felzenszwalb の方法）で輪郭からの距離を求め、マーチングスクエア法で線にしている。
内側の穴は埋める（細かい穴は切れないため）。A2 で 1 秒弱。

### 実装上の注意点（触るときに踏みやすい罠）

描画まわり:

- **細かい段は「重ねる」のではなく「消してから描く」。** 粗い段を下敷きにしたまま重ねると、
  線と線の隙間に下敷きのボケが残って濁る（隙間のアルファが 0 でなく 178 になる）。
- **拡大して描くときは `imageSmoothingEnabled = false`。** Chromium は補間を有効にしたまま拡大すると
  低解像度版を混ぜてしまい、隙間のアルファが 65 前後になる（high / medium / low いずれも同じ）。
  逆に縮小時は補間必須で、切ると細い線が消える。
- **段の選択には `devicePixelRatio` を掛ける。** 忘れると高精細ディスプレイで 1 段粗いマス目を使う。
- **100% は「画面の実ピクセル1つ＝画像の1ピクセル」。** 内部の倍率は CSS ピクセル基準なので、
  表示上の % は `zoom × devicePixelRatio`。これを揃えないとペイントソフトと大きさが合わない。
- **マス目の描画先は整数に丸める。** 隣り合うマス目が同じ境界値になるので継ぎ目が出ない。
- **レイヤー一覧の作り直しは 1 フレーム 1 回にまとめる。** タイル化のたびに作り直すと、
  枚数が多いときに DOM 構築が二乗に効いて固まる（200枚で1回18ms × 千回単位）。

Tauri / WebView2 まわり:

- **ウィンドウ設定の `dragDropEnabled` は false にする。** true だと OS 側のドラッグを横取りし、
  ページ内の並べ替えで掴んだ瞬間に禁止マークが出る（Tauri のソースに明記されている）。
- **行全体を draggable にしない。** 中のスライダーを掴むと行のドラッグが始まってしまう。
- **右クリックメニューとブラウザのショートカットは Rust 側で切る。** WebView2 の既定では、
  右クリックで「戻る・最新の情報に更新・印刷」が出て、F5 で再読み込みされる。Tauri の設定からは
  変えられないので、`with_webview` で WebView2 の設定を直接変えている。
- **フォルダを開くには `revealItemInDir` を使う。** opener プラグインの既定の権限には
  `open-path` が含まれていない。
- **WebView から触れる範囲は作業フォルダの直下と `_export` だけ。** 下の階層までは許可しない。
- **作業フォルダの場所を画面側で覚えておかない。** 覚えた値が古くなると別のフォルダから読んでしまう
  （実際に起きた）。読み書きのたびに Rust 側へ問い合わせる。
- **起動時に窓を作業領域（タスクバーを除いた範囲）へ収め直す。** 初期サイズ 1360×860 は、
  作業領域が 1440×852 の PC では下端がタスクバーの下に潜る。前回の形を覚える仕組みだけだと、
  はみ出した形が保存されて毎回はみ出す。前回の形はできるだけ残し、はみ出した分だけ縮める・ずらす。
  最大化中は「最大化を解除したときの形」を直す必要があり、Tauri の API では触れないので
  Win32 の `SetWindowPlacement` で直接書き換えている。
- **消えたファイルは少し待ってから一覧から外す。** 保存のしかたによっては上書きの途中で一瞬消えるため
  （1.5 秒）。設定は外したあとも保存しておき、同じ名前で戻ってきたら元の位置に戻す。

画質は、1px 幅の格子を描いた A2 画像を 100% 表示し、画面のピクセルが元PNGと完全一致する
（中間値が出ない）ことで検証している。Chrome と WebView2 の両方で確認済み。

## 構成

| | 役割 |
|---|---|
| `ui/index.html` `ui/style.css` | 画面 |
| `ui/app.js` | タイル描画・合成、レイヤー一覧、規格チェック、カットライン予想、メモリ管理 |
| `ui/tiler.js` | タイル生成と dpi 読み取りの Web Worker |
| `ui/backend.js` | バックエンドの抽象化。Tauri と HTTP の 2 実装 |
| `ui/licenses.txt` | 同梱しているオープンソースのライセンス一覧（自動生成） |
| `src-tauri/src/lib.rs` | フォルダ管理・一覧・空きメモリ・設定の読み書き・変更通知・ログ・WebView2 の設定 |
| `scripts/gen-licenses.mjs` | `ui/licenses.txt` を Cargo の依存関係から作る |
| `server.py` | 開発用のローカルHTTPサーバ（Python標準ライブラリのみ） |

## 開発

```bash
npm install          # 初回のみ
npm run dev          # アプリとして起動（Rust をビルドする）
npm run build        # ライセンス一覧を作り直してから、配布用の exe とインストーラを作る
```

描画まわりの検証はブラウザのほうが速い。`ui/backend.js` が自動で HTTP 実装に切り替わる。

```bash
python server.py "C:\path\to\parts" --port 8783
```

ビルド成果物:

- `src-tauri/target/release/layerdeck.exe` … 単体で動く実行ファイル
- `src-tauri/target/release/bundle/nsis/*.exe` … インストーラ

## 現状の制限・未対応

- クリッピングマスクは未対応（各パーツ内で処理してから書き出す前提）
- 合成モードの計算はペイントソフトと細部が異なる場合がある
- 起動のたびに全レイヤーのタイル化が走る（A2 6枚で約20秒、2並列。粗い段は先に届く）
- 書き出しPNGの圧縮率は指定できない（WebView のエンコーダ任せ）
- コード署名なし（初回起動時に Windows の警告が出る）
