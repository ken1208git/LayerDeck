# LayerDeck

パーツごとに別キャンバスで描いた**透過PNGを、フォルダに書き出すだけで自動的に重ね合わせて**
プレビューするデスクトップアプリ。

A2 / 350dpi（5787 × 8185 px）のような巨大キャンバスで、ペイントソフト側のレイヤー数を
増やさずに全体像を確認するためのもの。

## 何ができるか

- 指定フォルダを監視し、PNG が増えた／上書きされたら**自動で反映**
- **原寸のまま拡大できる**。何倍に拡大しても、絵が何枚あっても、使うメモリはほぼ一定
- レイヤーの表示切替・不透明度・**ブレンドモード17種**（乗算・スクリーン・加算ほか）
- 並べ替え（▲▼ボタン / ドラッグ / ファイル名の昇順）
- レイヤーごとの位置オフセット・拡大率・左右反転
- ズーム／パン、**左右反転チェック**、**グレースケール（明度チェック）**、背景切替
- 断ち切り・塗り足しガイド、dpi から mm 寸法を表示
- **原寸のまま合成PNGを書き出し**（監視フォルダの `_export/` に保存）
- レイヤー設定は監視フォルダの `layerdeck.project.json` に自動保存され、次回そのまま復元
- 前回開いていたフォルダを覚えていて、起動するとそこから始まる

## 使い方

1. `LayerDeck.exe` を起動（インストール版なら通常どおりスタートメニューから）
2. 「フォルダを選ぶ」でパーツPNGを置くフォルダを指定（次回からは自動で開く）
3. ペイントソフトから、そのフォルダに透過PNGを書き出す
4. 書き出すたびに勝手に更新される

### 運用のコツ

- ファイル名を `01_背景.png` `02_キャラ.png` … のように**数字プレフィックス**にしておくと、
  「名前順」ボタンで下から正しい順に積み直せる。
- 各パーツは**同じキャンバスサイズ**（例: A2 350dpi）で書き出すと位置合わせが不要になる。
- 目玉アイコンの **Alt+クリック** でそのレイヤーだけ表示（ソロ）。
- 書き出しは常に**元のPNGから原寸で**行われる。画面表示の都合は結果に影響しない。

### ショートカット

| キー | 動作 |
|---|---|
| ホイール | ズーム（カーソル基準） |
| ドラッグ | 移動 |
| `F` | 全体表示 |
| `1` | 等倍 |
| `H` | 左右反転チェック |
| `G` | グレースケール |
| `B` | 背景切替（市松／白／灰／黒） |

## 動作環境

Windows 10 / 11。WebView2 は Windows に標準で入っているため、**追加のインストールは不要**。

## 仕組み

PNG は途中の行だけを取り出せない形式なので、「見えている部分だけ読む」ことが原理的にできない。
そこで**読み込み時に一度だけフル展開し、1024px のマス目（タイル）に切り分けて持つ**。

```
PNGが更新される
  ↓ ① Web Worker がフル展開（190MB 級。worker の中だけに存在し、終わったら即解放）
  ↓ ② 1024px のマス目に切り分け、粗い段から順に返す
  ↓ ③ 以降は画面に映っているマス目だけを展開して描く
```

使用メモリが **画像サイズ × 枚数 ではなく、表示領域の広さ**で決まる。
A2 を 6 枚重ねて 100% 表示しても展開量は 150MB 程度（フル展開なら 1.1GB）。
A2/350dpi は 8185px あり、GPU が1枚のテクスチャとして扱える上限（環境により 8192px）に
近いという事情もあり、512〜1024px のマス目にしておくとその制約からも解放される。

展開量の上限は、**空き物理メモリの 25%**（96MB〜1.5GB）に自動で追従する。
ペイントソフトが重くなって空きが減れば、LayerDeck が自動で身を引く。
ウィンドウを裏に回したときも大半を手放す。**ディスクにキャッシュは作らない。**

### 実装上の注意点（触るときに踏みやすい罠）

- **細かい段は「重ねる」のではなく「消してから描く」。** 粗い段を下敷きにしたまま上に重ねると、
  線と線の隙間に下敷きのボケが残って濁る（隙間のアルファが 0 でなく 178 になる）。
- **拡大して描くときは `imageSmoothingEnabled = false`。** Chromium は補間を有効にしたまま
  拡大すると低解像度版を混ぜてしまい、透明であるべき隙間のアルファが 65 前後になる
  （high / medium / low いずれも同じ）。逆に**縮小時は補間必須**で、切ると細い線が丸ごと消える。
- **段の選択には `devicePixelRatio` を掛ける。** 忘れると高精細ディスプレイで 1 段粗いマス目を使う。
- **マス目の描画先は整数に丸める。** 隣り合うマス目が同じ境界値になるので継ぎ目が出ない。

これらは 1px 幅の格子を描いた A2 画像を 100% 表示し、画面のピクセルが元PNGと
完全一致する（中間値が出ない）ことで検証している。Chrome と WebView2 の両方で確認済み。

## 構成

| | 役割 |
|---|---|
| `ui/index.html` `ui/style.css` | 画面 |
| `ui/backend.js` | バックエンド抽象化。Tauri と HTTP の 2 実装 |
| `ui/app.js` | タイル描画・合成、レイヤーUI、メモリ管理 |
| `ui/tiler.js` | タイル生成 Web Worker |
| `src-tauri/src/lib.rs` | フォルダ管理・一覧・空きメモリ実測・設定の読み書き・変更通知 |
| `server.py` | 開発用のローカルHTTPサーバ（Python標準ライブラリのみ） |

画像の読み書きと合成はすべて WebView 側が行い、Rust 側は薄い。

## 開発

```bash
npm install          # 初回のみ
npm run dev          # アプリとして起動（Rust をビルドする）
npm run build        # 配布用の exe とインストーラを作る
```

描画まわりを細かく検証したいときは、ブラウザ側で動かすほうが速い。
`ui/backend.js` が自動で HTTP 実装に切り替わる。

```bash
python server.py "C:\path\to\parts" --port 8783
```

ビルド成果物:

- `src-tauri/target/release/LayerDeck.exe` … 単体で動く実行ファイル
- `src-tauri/target/release/bundle/nsis/*.exe` … インストーラ

## 現状の制限

- クリッピングマスクは未対応（各パーツ内で処理してから書き出す前提）
- 起動のたびに全レイヤーのタイル化が走る（A2 6枚で約20秒、2並列）。
  粗い段は先に届くので、待たされるのは 100% まで拡大したときの精細さだけ
- 書き出しPNGの圧縮率は指定できない（WebView のエンコーダ任せ）
