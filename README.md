# LayerDeck

パーツごとに別キャンバスで描いた**透過PNGを、フォルダに書き出すだけで自動的に重ね合わせて**
プレビューするローカルツール。

A2 / 350dpi（5787 × 8185 px）のような巨大キャンバスで、ペイントソフト側のレイヤー数を
増やさずに全体像を確認するためのもの。

## 何ができるか

- 指定フォルダを監視し、PNG が増えた／上書きされたら**自動で再読み込み**（0.8秒間隔）
- **原寸のまま拡大できる**。何倍に拡大しても、絵が何枚あっても、使うメモリはほぼ一定
- レイヤーの表示切替・不透明度・**ブレンドモード17種**（乗算・スクリーン・加算ほか）
- 並べ替え（▲▼ボタン / ドラッグ / ファイル名の昇順）
- レイヤーごとの位置オフセット・拡大率・左右反転
- ズーム／パン、**左右反転チェック**、**グレースケール（明度チェック）**、背景切替
- 断ち切り・塗り足しガイド、dpi から mm 寸法を表示
- **原寸のまま合成PNGを書き出し**（`_export/` に保存）
- 設定は監視フォルダの `layerdeck.project.json` に自動保存され、次回そのまま復元

## 動作環境

- Windows（macOS でも概ね動く。`📂` ボタンだけ Windows 専用）
- Python 3.8 以降 … **標準ライブラリのみ。`pip install` は不要**
- Chrome / Edge などの最近のブラウザ

## 使い方

1. `LayerDeck起動.bat` をダブルクリック（黒い窓が出てブラウザが開く）
2. 「フォルダを選ぶ」でパーツPNGを置くフォルダを指定
3. ペイントソフトから、そのフォルダに透過PNGを書き出す
4. 書き出すたびにブラウザ側が勝手に更新される

黒い窓は動作中ずっと開いたままにしておく。閉じると終了。

コマンドラインから直接起動する場合:

```bash
python server.py "C:\path\to\parts" --port 8777
```

## 運用のコツ

- ファイル名を `01_背景.png` `02_キャラ.png` … のように**数字プレフィックス**にしておくと、
  「名前順」ボタンで下から正しい順に積み直せる。
- 各パーツは**同じキャンバスサイズ**（例: A2 350dpi）で書き出すと位置合わせが不要になる。
- 目玉アイコンの **Alt+クリック** でそのレイヤーだけ表示（ソロ）。
- 書き出しは常に**元のPNGから原寸で**行われる。画面表示の都合は結果に影響しない。

## 仕組み

PNG は途中の行だけを取り出せない形式なので、「見えている部分だけ読む」ことが原理的にできない。
そこで**読み込み時に一度だけフル展開し、512px のマス目（タイル）に切り分けて持つ**。

```
PNGが更新される
  ↓ ① Web Worker がフル展開（190MB 級。worker の中だけに存在し、終わったら即解放）
  ↓ ② 512px のマス目に切り分け、粗い段から順に返す
  ↓ ③ 以降は画面に映っているマス目だけを展開して描く
```

これにより、使用メモリが **画像サイズ × 枚数 ではなく、表示領域の広さ**で決まる。
A2 を 6 枚重ねて 100% 表示しても展開量は 50〜90MB 程度（フル展開なら 1.1GB）。

展開量の上限は、サーバが実測した**空き物理メモリの 25%**（96MB〜1.5GB）に自動で追従する。
ペイントソフトが重くなって空きが減れば、LayerDeck が自動で身を引く。
タブを裏に回したときも大半を手放す。**ディスクにキャッシュは作らない。**

### 実装上の注意点（触るときに踏みやすい罠）

- **細かい段は「重ねる」のではなく「消してから描く」。** 粗い段を下敷きにしたまま上に重ねると、
  線と線の隙間に下敷きのボケが残って濁る。
- **拡大して描くときは `imageSmoothingEnabled = false`。** Chrome は補間を有効にしたまま拡大すると
  低解像度版を混ぜてしまい、透明であるべき隙間のアルファが 0 でなく 65 前後になる
  （high / medium / low いずれも同じ）。逆に**縮小時は補間必須**で、切ると細い線が丸ごと消える。
- **段の選択には `devicePixelRatio` を掛ける。** 忘れると高精細ディスプレイで 1 段粗いマス目を使う。
- **マス目の描画先は整数に丸める。** 隣り合うマス目が同じ境界値になるので継ぎ目が出ない。

## 構成

| ファイル | 役割 |
|---|---|
| `server.py` | ローカルHTTPサーバ。フォルダ監視API・画像配信・空きメモリ実測・フォルダ選択・書き出し保存 |
| `index.html` | 画面 |
| `app.js` | タイル描画・合成、レイヤーUI、メモリ管理、ポーリング |
| `tiler.js` | タイル生成 Web Worker |
| `style.css` | 見た目 |

サーバは `127.0.0.1` にのみバインドし、外部からはアクセスできない。
配信するのは監視フォルダ直下のファイルのみ（パストラバーサル対策済み）。

## 現状の制限

- クリッピングマスクは未対応（各パーツ内で処理してから書き出す前提）
- 起動のたびに全レイヤーのタイル化が走る（A2 1枚あたり約4秒、2並列）。
  粗い段は1秒足らずで揃うので、待たされるのは 100% 拡大したときの精細さだけ
- 書き出しPNGの圧縮率は指定できない（ブラウザのエンコーダ任せ）
